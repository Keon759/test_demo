# AI 自动化测试插件最小原型架构方案

## 1. 原型目标

验证插件能否围绕一个 PRD 文本完成自动化测试闭环：

PRD 文本解析 -> 需求结构化 -> 测试用例生成 -> 接口/页面执行 -> 报告生成 -> Bug 单生成/推送。

## 2. 核心模块

| 模块 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| PRD 解析器 | PRD 文档 | 功能点、规则、验收标准 | 使用大模型抽取结构化需求 |
| 需求拆解器 | 结构化需求 | 需求编号、优先级、风险点 | 将自然语言转为可测试条目 |
| 用例生成器 | 需求条目 | 正向/反向测试用例 | 基于规则生成边界值、异常值 |
| 执行器 | 测试用例、接口定义、页面地址 | 执行结果 | 支持接口测试和页面测试 |
| 报告生成器 | 执行结果、缺陷列表 | 测试报告 | 汇总通过率、失败原因、质量结论 |
| Bug 生成器 | 失败用例、需求引用、实际结果 | 标准化 Bug 单 | 可扩展推送 Jira、禅道、飞书等 |

## 3. 执行链路

1. 输入 PRD 文档。
2. 大模型识别功能模块、业务规则和验收标准。
3. 自动生成需求矩阵和测试点。
4. 基于测试点生成测试用例。
5. 对接口或页面执行自动化测试。
6. 对比预期结果和实际结果。
7. 失败用例自动生成 Bug 单。
8. 汇总生成测试报告。

## 4. Demo 闭环验证

本项目中，PRD 声明“用户名长度必须大于等于 6 位”。测试用例生成器应生成短用户名反向用例：

- 输入：`username=abc`
- 预期：注册失败，返回 400
- 实际：注册成功，返回 201

插件据此生成 `BUG-REG-001`，完成最小闭环。

## 5. 后续扩展方向

- 接入 Playwright 执行页面自动化。
- 增加 OpenAPI/Swagger 解析能力。
- 将测试用例输出为 Excel、Markdown 或测试管理平台格式。
- 支持 Bug 平台自动推送。
- 支持多轮 Prompt 修正，减少用例遗漏。
- 增加需求变更差异分析，自动补充回归用例。
