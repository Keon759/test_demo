# 项目表述与时间边界

## 原始实习原型的表述建议

基于实际原始成果，可使用：

- 基于 React、Flask 和 SQLite 搭建登录注册 PoC 沙盒，预埋用户名长度校验缺陷，为自动化测试插件方案提供验证场景。
- 围绕 PRD 拆解注册与登录业务规则，设计正反向测试用例，整理预期结果、手工/接口执行记录、报告和标准化 Bug 单。
- 设计 PRD 解析、需求拆解、用例生成、执行、报告及 Bug 推送的插件架构，利用沙盒和样例交付物模拟完整测试流程。

原始成果不应表述为已经开发完毕的 Prompt 引擎、多轮 Agent、自动提交外部工单或无需人工编辑的全套 AI 流程，除非另有对应实现和运行证据。

## 2026-10-13 后续完善成果

可作为项目的持续完善单独描述：

- 实现受限 PRD 规则解析与接口测试执行管道，围绕 10 条业务需求生成 13 条用例，自动输出需求、用例、执行记录、报告和本地缺陷单五类资产。
- 通过预埋缺陷与修复模式验证流程：缺陷模式 12 条通过、1 条失败并产生 1 张缺陷单；同一计划修复回放 13 条全部通过。
- 增加 React / Ant Design 演示面板、结构化结果下载及 Windows / Ubuntu 持续集成配置。
- 编写可选 OpenAI 结构化输出接入、Prompt 与计划校验，完成模拟响应测试；真实 API 运行效果尚待验证。

13 条业务用例属于离线规则模式，不能称为已验证的大模型生成效果；本地生成缺陷单不能写成已提交 Jira / GitHub 工单。
